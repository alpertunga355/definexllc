Engineering

A prompt is the weakest place to put a guarantee.

Most agent failures are not model failures. They are a safety property placed at a layer that cannot hold it. This is the hierarchy DefineX builds against, and what is and is not allowed at each level.

01

Four layers, cheapest to strongest

A property belongs at the lowest layer that can actually guarantee it — never higher.
LayerHoldsNever holds
01 PromptIntent, voice, framing, what good looks like.Arithmetic, limits, or any mechanical safety property.
02 ContextRetrieved facts, indexed source material, bounded tool output.Guarantees — context shapes an answer, it cannot force one.
03 HarnessValidators, typed schemas, decorators, rules engines. Deterministic code.Judgement calls that genuinely need a model.
04 LoopTest suites, baseline receipts, circuit breakers. Exit code zero or it did not happen.Anything that cannot be re-run unattended.

02

Three lanes of action

An autonomous agent needs an approval boundary drawn by reversibility, not by how risky something sounds.

Lane 1

Reversible

Executed autonomously, no confirmation.

  • Reading and searching
  • Writing code and tests
  • Branches and local commits
  • Scratch and data writes

Lane 2

Consequential

Prepared to completion, then confirmed once, with a diff to read.

  • Deploys
  • Pushes to the default branch
  • Scheduled task changes
  • External writes

Lane 3

Irreversible

Hard stop. Parked for a human decision, every time.

  • Live-capital execution
  • Dropping a volume or database
  • Force-push
  • Anything public and permanent

03

The verification standard

A quantitative claim is not accepted because the system that produced it is confident. It is handed to a reviewer with a fresh context, given only the hypothesis, the script and the raw log, and returned as one of three verdicts.

  • VERIFIED — reproduced from the raw log independently.
  • REFUTED — the number does not follow from the data.
  • OVERFIT — reproducible, but not evidence of anything.

This layer is not theoretical caution. It exists because self-review has already passed fabricated results here, and a reviewer that cannot see the reasoning cannot agree with it out of politeness.

Operating thesis

  • A single operator with the right harness outperforms a team with the wrong one.
  • Model output is a hypothesis. Deterministic code is the verdict.
  • Anything that cannot be re-run and re-verified is not shipped.

Output discipline

Tool and test output is compacted to a bounded summary with the full transcript written to a run log. An agent that drowns in its own output stops reasoning about it.

04

What this buys

  1. Autonomy without supervision cost

    Reversible work proceeds without asking. The approval budget is spent only where a mistake cannot be undone.

  2. Failures that announce themselves

    Fail-closed defaults mean a broken input produces a stop, not a confident wrong answer that reaches a dashboard.

  3. A marginal cost that falls

    Constraints encoded once are asserted on every build thereafter. The second system in a domain is cheaper than the first, and the fifteenth title cheaper than the fourteenth.
